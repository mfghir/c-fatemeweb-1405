# fatemeweb — پورتفولیو بازطراحی‌شده

پورتفولیو سه‌زبانه (فارسی / English / 한국어) با سه حالت ظاهری (لایت / دارک / رترو)، صفحهٔ اصلی + صفحهٔ نمونه‌کارها با جستجو و فیلتر + صفحهٔ جزئیات برای هر پروژه. با **Next.js 15 (App Router)**، **TypeScript**، **Tailwind CSS v4** و **shadcn/ui** ساخته شده.

## اجرا

```bash
npm install
npm run dev
```

سپس به آدرس `http://localhost:3000` بروید.

- صفحهٔ اصلی: `/`
- همهٔ نمونه‌کارها (با جستجو و فیلتر): `/works`
- جزئیات هر پروژه: `/works/[id]`

## این دور: TypeScript + shadcn/ui، و چند رفع‌اشکال

- **بازنویسی کامل با TypeScript + shadcn/ui:** همهٔ فایل‌ها از `.jsx`/`.js` به `.tsx`/`.ts` تبدیل شدن. تایپ‌های مشترک (`Project`, `Copy`, `Locale`, `Theme`) توی `lib/types.ts` تعریف شدن. کامپوننت‌های فرم و دکمه و غیره حالا از `shadcn/ui` میان (`components/ui/button.tsx`, `input.tsx`, `textarea.tsx`, `select.tsx`, `badge.tsx`) — بر پایهٔ Radix UI، با همون توکن‌های رنگی سایت (`--primary`, `--background` و غیره) سفارشی‌سازی شدن، پس ظاهرش دقیقاً همونیه که قبلاً بود.
- **دکمهٔ «نمایش بیشتر» خالی بود:** این به‌خاطر یک باگ کوچیک توی نسخهٔ قبلی بود (رشتهٔ متن درست جایگزین نشده بود). توی بازنویسی TS دوباره از صفر تایپ شد و مطمئن شدم `t.loadMore` هر سه زبان مقدار داره.
- **سرچ‌بار و فیلتر توی یک سطر:** توی `/works`، روی دسکتاپ سرچ‌بار و فیلتر کنار هم توی یک ردیف هستن (`flex-row`)؛ روی موبایل زیر هم می‌رن.
- **فیلتر با Select به‌جای دکمه‌های جدا:** دکمه‌های پیل دسته‌بندی جاشون رو به یک `<Select>` (شادکن/Radix) دادن — یک دراپ‌داون تمیزتر، به‌خصوص وقتی تعداد دسته‌ها زیاد بشه.
- **ساختار هدر عوض شد:** به‌جای چیدمان قبلی (لوگو+ناوبری با هم توی سمت چپ)، حالا سه‌ناحیه‌ست: لوگو در یک سمت، ناوبری دقیقاً وسط صفحه (نه فقط وسط فضای خالی)، و سوییچرهای زبان/تم در سمت دیگه — چیدمان رایج‌تر و متعادل‌تر برای یک هدر پورتفولیو.

## ساختار

- `app/layout.tsx` — لایوت اصلی؛ Header، Footer، نوار پیشرفت اسکرول و SiteProvider (زبان/تم) رو دور همهٔ صفحات می‌پیچه
- `app/page.tsx`, `app/works/page.tsx`, `app/works/[id]/page.tsx` — مسیرهای سه‌گانهٔ سایت
- `components/SiteContext.tsx` — مدیریت زبان/تم/۳ پالت رنگی (ذخیره در localStorage)
- `components/Header.tsx` / `Footer.tsx` — مشترک بین صفحات
- `components/Home.tsx` — محتوای صفحهٔ اصلی (هیرو، درباره، تخصص، روند کار، پیش‌نمایش نمونه‌کارها، فرم تماس)
- `components/WorksPage.tsx` — لیست کامل با جستجو + فیلتر Select + دکمهٔ نمایش بیشتر
- `components/WorkDetail.tsx` — صفحهٔ جزئیات یک پروژه (قبلی/بعدی، لینک مشاهده)
- `components/WorkCard.tsx` — کارت پروژه (به `/works/[id]` لینک می‌ده)
- `components/copy.ts` — متن‌های سه‌زبانه + خواندن داده از API
- `components/useProjects.ts` — هوک گرفتن نمونه‌کارها از API
- `components/Reveal.tsx` — انیمیشن fade-in موقع اسکرول
- `components/Toast.tsx` — نوتیفیکیشن موفقیت/خطا برای فرم تماس
- `components/ui/*.tsx` — کامپوننت‌های پایهٔ shadcn (button, input, textarea, select, badge)
- `lib/types.ts` — تایپ‌های مشترک تایپ‌اسکریپت
- `lib/utils.ts` — تابع کمکی `cn()` برای ترکیب کلاس‌های Tailwind
- `.env.local` — کلیدهای EmailJS (از قبل با مقادیر تو پر شده)

## رنگ اصلی

`#007BFF` — به‌صورت CSS variable با نام `--primary` تعریف شده (`app/globals.css`، هماهنگ با قرارداد رنگی shadcn) و در هر سه تم (لایت/دارک/رترو) به‌عنوان رنگ برند ثابت می‌مونه.

## سه تم: لایت / دارک / رترو

سوییچر تم در ناوبار سه حالته‌ست (آیکون خورشید/ماه/تلویزیون). تم رترو یک پالت گرم و کاغذی (کِرِم + قهوه‌ای تیره) با بافت اسکن‌لاین ظریف و فونت تایپ‌رایتری (`Space Mono`) برای تیترها داره — رنگ آبی برند در هر سه تم ثابت می‌مونه. تعریف پالت‌ها در `app/globals.css` (کلاس‌های `:root`, `.dark`, `.retro`).

## متن‌ها — بهینه برای کارفرما/ریکروتر

تگ‌لاین، توضیح هیرو، و بج «آمادهٔ همکاری» در هر سه زبان روی نتیجه و ارزش کسب‌وکاری تمرکز دارن. یک بخش «دقیقاً چه کاری انجام می‌دهم» (`Expertise`) هم بین «درباره» و «روند کار» هست: چهار کارت مشخص — پژوهش و استراتژی، طراحی UI، سیستم طراحی، هندآف و همکاری با توسعه. متن‌ها در `components/copy.ts`.

## فرم تماس — اعتبارسنجی، اعلان، و EmailJS

- هر فیلد (نام، ایمیل، پیام) موقع خالی یا نامعتبر بودن، خطای مخصوص خودش رو زیرش نشون می‌ده؛ فرمت ایمیل با regex بررسی می‌شه و در صورت نامعتبر بودن اصلاً درخواستی ارسال نمی‌شه.
- بعد از تلاش برای ارسال، یک toast پایین صفحه موفقیت/شکست رو نشون می‌ده (`components/Toast.tsx`).
- ارسال با SDK رسمی `@emailjs/browser` انجام می‌شه. کلیدها دقیقاً با همون اسم‌هایی که خودت استفاده می‌کردی از `.env.local` خونده می‌شن:

```
NEXT_PUBLIC_APP_SERV=service_mvy485h
NEXT_PUBLIC_APP_TEMP=template_3unplb2
NEXT_PUBLIC_APP_KEY=ikAgJ0NQP9m1rJohf
```

اگه بازم پیام ارسال نشد، بخش «ایمیل — تشخیص دقیق‌تر مشکل» پایین‌تر رو ببین.

## نمونه‌کارها — شکل واقعی API

هر آیتم این شکل رو داره:

```json
{
  "id": 1,
  "category": "web",
  "title": "Rovella",
  "imgUrl": "https://...",
  "gitLink": "https://github.com/...",
  "onlineLink": "https://....netlify.app",
  "tags": ["html", "css"]
}
```

`normalizeProject` در `components/copy.ts` دقیقاً همین فیلدها رو می‌خونه:
- `category` → برچسب روی کارت + گزینه‌های فیلتر در `/works`
- `tags` → چیپ‌های کوچک تکنولوژی روی کارت و صفحهٔ جزئیات
- `imgUrl` → عکس کارت (با `<img referrerPolicy="no-referrer">` برای دور زدن محدودیت هات‌لینک بعضی هاست‌های عکس مثل postimg.cc؛ اگه لینک خراب بود، خودکار به پلاسهولدر رنگی سوییچ می‌کنه)
- `onlineLink` → دکمهٔ «مشاهدهٔ آنلاین»
- `gitLink` → دکمهٔ «مشاهدهٔ کد» (فقط وقتی مقدار داره نمایش داده می‌شه)
- `description`/`desc`/`content`/`body` (هرکدوم موجود بود) → متن توضیح پروژه. **این فیلد فعلاً توی API نیست** — جاش توی صفحهٔ جزئیات رزرو شده و تا وقتی اضافه‌ش نکنی یک متن جای‌نگهدار نشون داده می‌شه.

- صفحهٔ اصلی: ۳ مورد اول با لینک «مشاهدهٔ همهٔ نمونه‌کارها»
- `/works`: لیست کامل، ۶ تا ۶ تا با دکمهٔ «نمایش بیشتر»، با سرچ‌بار و Select فیلتر دسته که با هم ترکیب می‌شن
- هر کارت به `/works/[id]` لینک می‌ده: صفحهٔ جزئیات با عکس بزرگ‌تر، توضیح کامل، دکمهٔ «مشاهدهٔ آنلاین»/«مشاهدهٔ کد»، و ناوبری پروژهٔ قبلی/بعدی

اگه API چیزی برنگردونه، یک کارت با لینک مستقیم به دریبل (`https://dribbble.com/fatemeweb`) جایگزین می‌شه.

## ایمیل — تشخیص دقیق‌تر مشکل

اگه فرم بازم کار نکرد:

1. اول به فرم نگاه کن — اگه یک هشدار قرمز زیر دکمهٔ ارسال دیدی («EmailJS env vars aren't loaded…»)، یعنی مقادیر `.env.local` اصلاً لود نشدن. این یعنی یا `npm run dev` رو بعد از اضافه/ویرایش `.env.local` ری‌استارت نکردی، یا (اگه دیپلوی کردی) متغیرها رو در تنظیمات محیطی هاست (Netlify/Vercel) نذاشتی و دوباره دیپلوی نکردی.
2. اگه اون هشدار رو ندیدی ولی بازم ایمیل نرسید، Console مرورگر (F12 → Console) رو باز کن و دکمهٔ ارسال رو بزن. باید خط `[contact form] submit clicked` ظاهر بشه:
   - اگه این خط اصلاً ظاهر نشد → پروژه رو دوباره `npm install` کن (چون پکیج‌های جدید مثل `@emailjs/browser` و shadcn اضافه شدن) و مطمئن شو داری آخرین نسخهٔ فایل‌ها رو اجرا می‌کنی.
   - اگه ظاهر شد ولی بعدش خطا دید (`[contact form] EmailJS send failed: ...`) → متن دقیق خطا رو بخون؛ معمولاً یا شناسهٔ سرویس/تمپلیت اشتباهه یا دامنه‌ای که داری تستش می‌کنی توی «Allowed origins» داشبورد EmailJS نیست.
   - اگه دید `[contact form] EmailJS success: 200 OK` و بازم چیزی به ایمیلت نرسید → توی داشبورد EmailJS برو به تمپلیتت و مطمئن شو فیلد **«To Email»** (تنظیمات تمپلیت، نه محتوای متن) دقیقاً به ایمیل خودت ست شده — رایج‌ترین دلیل «ارسال بدون خطا ولی بدون نتیجه»‌ست. پوشهٔ اسپم/Junk رو هم چک کن.
3. مطمئن‌ترین راه: توی داشبورد EmailJS برو به بخش **Email History** — هر تلاش (موفق یا ناموفق) اونجا با جزئیات کامل لاگ می‌شه، مستقل از هر چیزی که توی کد یا کنسول مرورگر می‌بینی.

**نکتهٔ مهم:** هر بار فایل‌های جدید رو جایگزین پروژه‌ات می‌کنی، حتماً یک بار `npm install` بزن (چون `package.json` هر بار پکیج جدید گرفته) و اگه روی Netlify/Vercel دیپلوی شده، دوباره push/deploy کن.

## دیپلوی

برای Netlify یا Vercel کافیست ریپو را متصل کنید و متغیرهای `.env.local` رو در تنظیمات محیطی (Environment Variables) پروژه هم اضافه کنید؛ نیازی به تنظیم خاص دیگه‌ای نیست.
